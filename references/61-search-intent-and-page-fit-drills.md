# 61 — 搜尋意圖與頁面對應練習

**reason**：把查詢、SERP 頁型、讀者任務與自站承接頁放在同一個小練習裡，避免只看字面或單一工具數字就決定新建、重寫或合併。
**strip_when**：若教學不再處理查詢選擇、SERP 判讀或頁面歸屬，才移除；概念定義仍可直接回答，不必啟動完整練習。

這份練習接在 `55-search-opportunity-lab.md` 的 G3 使用。它不是關鍵字清單、排名保證或自動分群器；每次只挑一個查詢和一個可能的承接頁。

## 四個判讀層

對同一個查詢依序問：

1. **讀者任務**：他想理解、比較、選擇、購買、找一個特定頁面，還是解決一個當下問題？
2. **SERP 頁型**：自然結果目前主要是教學頁、比較頁、產品／服務頁、分類頁、論壇、影片、工具或其他可觀察格式？
3. **承諾與內容**：前排頁面承諾回答什麼；自站現有頁面真正回答什麼？
4. **業務與能力**：網站是否服務這個受眾，且能用可靠資料、經驗或服務完成承諾？

意圖標籤只是工作語言，可先用資訊型、商業調查、交易型、導航型、在地／即時／工具型等標籤。若頁型互相衝突，記為 `mixed / uncertain`，不要逼出單一答案；SERP 的實際觀察優先於查詢字面。

## 一頁一個主要任務

「一個查詢只配一頁」不是絕對規則，而是初學者的安全起點。當兩頁的受眾、任務或頁型明顯不同，可以保留兩頁；若只是換了幾個同義詞，卻回答同一個任務，先標為頁面競爭候選，再查：

- 該查詢在不同時間是否交替顯示不同 URL；
- 兩頁是否真的各自服務不同任務；
- 哪一頁有更直接的第一方資料、轉換路徑或讀者下一步；
- 合併、差異化、保留觀察或暫緩，哪個選擇最可回復。

「搜尋競爭頁」只表示它在同一 SERP 中承接相近任務，不等於它是商業上的直接競爭者，也不代表網站必須模仿它。

## 四種頁面決定

| 決定 | 適用條件 | 下一個小檢查 |
|---|---|---|
| `new` | 沒有合適承接頁，且讀者任務、業務價值與可信能力都成立 | 寫出一個任務與三個必要問題 |
| `improve` | 已有頁面能承接，問題是覆蓋、證據、清晰度或新鮮度不足 | 指出保留／加強／新增各一項 |
| `defer` | 有候選需求，但資料、受眾或能力仍不足 | 寫出補證據條件與回查日期 |
| `do-not-target` | 只有他站覆蓋，與受眾、業務或能力不吻合 | 記錄不做理由，不硬湊缺口 |

任何 `new` 或 `improve` 決定都要能連到一張證據卡；必要時連一張假設卡。沒有自站檢查或 SERP 證據時，只能停在候選，不直接排進優先工作。

## 一輪練習卡

```markdown
查詢：
讀者任務：
地區／語言／裝置／日期：
看到的前 1–3 個自然結果：URL／頁型／標題承諾
主要意圖：[單一 / mixed / uncertain]
目前自站承接頁：[URL / 無 / 待查]
頁面決定：[new / improve / defer / do-not-target]
理由：一個 SERP 觀察 + 一個自站或業務證據
不能推出：
下一個檢查：
```

新手第一輪由教練示範一筆；第二筆共做；第三筆由學員獨立判讀。若三筆仍混合，只加兩筆，不預設掃完整前十名。學員能說明「為什麼這頁適合／不適合」且能提出反證條件，才算完成這個練習，而不是只背意圖名稱。

## 常見誤判修正

- 把查詢中出現「買」「比較」當成交易意圖：先看自然結果的頁型與標題承諾。
- 把競品有寫當成讀者一定需要：補查受眾、需求、可信能力與業務目的。
- 看到多頁都提到同一詞就自動合併：先查任務是否相同，再決定。
- 看到一個高曝光查詢就馬上改頁：先確認承接頁、當下 SERP、資料範圍與修改前基準。
- 把沒有觀察到的 SERP 功能寫成沒有：記為未觀察，必要時補一張截圖。
