# GSC 面板（GSC Panel）

**reason**：提供一個即時讀取 Search Console API、可重做的資料閱讀與複查入口，讓學員有一致的總覽、頁面、關鍵詞、分組與工具分頁，再把真正的 SEO 判斷交回 SERP、頁面與第一方證據。
**strip_when**：若不再發佈 GSC 面板，才移除；GSC 概念教學仍可保留其他一般指南。

**用途：** 學員已接好 GSC API（預設走 `65-gsc-api-setup.md` 的本機工具）時，用瀏覽器開啟面板，看整站總覽、頁面衰退、新頁面、排名追蹤、黃金距離、蠶食、語言版本、分組趨勢、索引檢查、變更前後對照、原始資料匯出，以及教練的行動佇列。它是資料閱讀與下一步排序工具，不是完整 SEO audit，也不會代替學員判斷搜尋意圖或直接重寫文章。

面板入口：執行 `node assets/gsc-tools/gsc.mjs serve` 後開啟 `http://127.0.0.1:8791/`；檔案本體是 `assets/gsc-dashboard/index.html`（畫面名稱 GSC Panel）。

## 固定邊界

- 面板只走 GSC API，不處理登入、不保存或讀取憑證，也不對外開任何連線。它唯一會發出的請求是本機工具伺服器的同源 `api/` 路由（`local.js`）；金鑰只由本機工具讀取，不會送到頁面。**CSV／TSV／JSON 成效匯入已移除**；檔案匯入只剩排名追蹤的關鍵詞清單，以及學員自己的筆記與設定備份。
- 沒有任何連線時，面板顯示設定步驟與「載入示範資料」。示範資料是內建的合成資料（`demo.js`），畫面上有明顯標示，不可當成任何網站的成效；可當練習場（→ `48-practice-reading-drills.md`）。
- GSC 資料不落地：面板不把 API 回傳的列寫進 `localStorage`，只在記憶體內快取到重新整理為止。保存在該瀏覽器的只有使用者自己的東西：語言與主題選擇、選定的網站資源與期間、追蹤關鍵詞、分組、變更筆記、行動佇列的狀態與備註、規則門檻。「清除本機資料」會全部移除；設定選單可把這些筆記與設定匯出成 JSON，換瀏覽器或電腦時再匯入。
- 所有計算都是 deterministic，放在 `engine.js`；面板不呼叫 AI、Codex CLI 或任何外部服務。
- 各分頁列出的都是人工複查候選，不是 Google 建議，也不是自動判定「一定要改」。
- GSC 的平均排名是期間平均位置，不是某個人此刻在 SERP 看到的名次；查詢維度不含匿名查詢。
- 只請求最終資料（`dataState: "final"`），結束日固定為今天往前 3 天。GSC 約保留 16 個月資料，超過這個範圍的比較期間不會被硬湊出來。

面板完成資料整理後，若要判斷接近首頁、內容衰退或多頁承接，轉讀 `62-gsc-diagnosis-drills.md`；面板的排序與門檻仍只是人工複核入口，不是修改命令。

## 語言：跟著對話語言，內建三種

- 內建只有 `zh-Hant`、`zh-Hans`、`en` 三個語系檔。**其他語言不預先寫好**，由教練在第一次替該學員設定面板時，依學員與教練交談的語言生成一次。
- 面板語言由教練指定，寫在 `assets/gsc-dashboard/panel-config.js` 的 `locale`。教練第一次帶學員開面板時：

  1. 判斷學員與你交談使用的語言，對應成語系標籤（繁中 `zh-Hant`、簡中 `zh-Hans`、英文 `en`，其他如 `ja`、`ko`、`de`、`pt-BR`）。
  2. 若是內建三種之一：直接執行 `node assets/gsc-tools/locale.mjs --use <tag>`。
  3. 若不是內建語言，做一次而且只做一次：
     - `node assets/gsc-tools/locale.mjs <tag> "<該語言的自稱名>" [ltr|rtl]`（例：`node assets/gsc-tools/locale.mjs ja "日本語" ltr`；阿拉伯文、希伯來文用 `rtl`）。
     - 把新檔 `assets/gsc-dashboard/locales/<tag>.js` 的每一個值翻成學員語言。保留 key 名稱、`{{placeholder}}`，以及 GSC／API／CSV／CTR／SERP／URL Inspection／Canonical／regex／connector 這類術語。
     - `node assets/gsc-tools/locale.mjs --check <tag>` 確認沒有缺 key、沒有 placeholder 不一致，並看還有幾個值仍是英文。
     - `node assets/gsc-tools/locale.mjs --use <tag>`（在維護用 repo 內再執行 `node scripts/test_gsc_dashboard.mjs`）。
  4. 請學員重新整理面板，並在設定選單的語言確認。

- 面板決定語言的順序：網址 `?lang=<tag>` → 學員在這個瀏覽器手動選過的語言 → `panel-config.js` 的 `locale`（對話語言）→ 瀏覽器語言 → 英文。指定的語言不在已載入的清單時，面板會用動態插入的 `<script>` 嘗試載入 `locales/<tag>.js`（先完整標籤，再基底標籤），找不到或逾時（3 秒）就靜默退回下一順位。
- 之後不再重複翻譯該語言，也不要在面板執行期呼叫 AI；面板只讀已存在的語系檔。學員中途換語言交談時，再執行一次 `--use`（必要時先生成該語言）。
- 宿主頁面若已持有字典，也可用 `window.SEOCoachGscDashboard.registerLocale(tag, dictionary, { activate: true })` 直接註冊；`listLocales()` 列出已載入語系，`setLocale(tag)` 切換。

## 連線：三個順位

面板載入時依序找：① 宿主頁面提供的 `window.SEOCoachGscConnector` → ② 本機工具伺服器（自動偵測）→ ③ 連線說明畫面（設定步驟與示範資料按鈕）。

- **大多數學員走 ②**：`node assets/gsc-tools/gsc.mjs serve [--port 8791]`，只綁定 `127.0.0.1`。同一把服務帳戶金鑰同時供面板與教練的 CLI 使用；設定、錯誤對照與安全規則 → `65-gsc-api-setup.md`。伺服器已啟動但找不到金鑰時，面板顯示「本機服務已啟動，還差金鑰」與預設金鑰路徑。
- **① 是給已有自己連線層的宿主**（契約第 2 版，未變）：載入前提供物件，或載入後呼叫 `window.SEOCoachGscDashboard.connect(connector)`。登入、授權與實際 API 呼叫都由宿主負責。

| 方法 | 必要 | 對應與形狀 |
|---|---|---|
| `listSites()` | 是 | `sites.list` → `[{ siteUrl, permissionLevel }]` |
| `query(request)` | 是 | `searchanalytics.query`；request 帶 `{ siteUrl, startDate, endDate, dimensions, type: "web", dataState: "final", rowLimit (≤ 25000), startRow, dimensionFilterGroups? }` → `{ rows: [{ keys, clicks, impressions, ctr, position }] }` |
| `inspectUrl(request)` | 選用 | `urlInspection.index.inspect`；沒有就停用「索引檢查」 |
| `fetchSitemapUrls(request)` | 選用 | `{ siteUrl, sitemapUrl }` → 網址陣列；沒有就只能貼上網址清單 |
| `listUpdates({ since })` | 選用 | `[{ date, end, title, url, source }]`；沒有就不顯示更新標記 |

- `dimensions` 可以是 `date`、`query`、`page`、`country`、`device` 的任意組合，`keys` 順序對應 `dimensions`；篩選使用 API 原生運算子（`contains`、`notContains`、`equals`、`notEquals`、`includingRegex`、`excludingRegex`）。
- 物件必須帶 `version: 2`；只提供舊版 `load()` 的第 1 版不再相容，面板會顯示「連線版本過舊」。
- 單次請求最多 25,000 列；達到上限時面板標示結果可能不完整。
- `window.SEOCoachGscDashboard` 另有 `refresh()`、`loadDemo()`、`getState()`。測試用宿主頁：`qa/gsc-dashboard/api-bridge.html`（需用本機 http 伺服器開啟）。

## 面板計算

### 頁面的認定

- Search Console 會把搜尋結果的跳轉連結（`/a.html#sec-1`）回報成獨立的頁面列。面板在比較或加總頁面前先去掉 `#` 之後的部分，同一頁的錨點併回該頁：點擊與曝光相加，平均排名以曝光加權。衰退熱圖、新頁面、排名追蹤、黃金距離、蠶食與行動佇列都依這個規則。
- `#!` 與 `#/` 開頭的是前端路由，視為不同頁面，不合併。
- 「原始資料匯出」維持 GSC 回傳的原樣，仍看得到個別錨點列。
- 併回後，同一查詢下某頁的曝光可能高於 GSC 介面裡該網址單列的數字，因為主結果與跳轉連結各算一次曝光。

### 總覽指標

- 點擊、曝光：以 `date` 維度的每日列加總，因此包含匿名查詢的流量。
- CTR：`總點擊 ÷ 總曝光`，不把每列 CTR 做簡單平均；變化以百分點（pt）顯示。
- 平均排名：以曝光數作權重匯總；沒有曝光但有排名的列使用 1 作最低權重。
- 查詢列的點擊加總小於總點擊超過 1% 時，面板會註明約有多少比例來自 GSC 沒有列出的查詢。

### 排名分桶

每個查詢的期間平均排名**四捨五入到整數**後落入：`1–3`、`4–10`、`11–20`、`21–30`、`31–50`、`51+`。這是閱讀分布的區間，不是成效保證或 Google 的固定分級。

### 前後期變化

- 排名變化＝`前期平均排名 − 目前平均排名`。正數代表數字變小、位置往前。預設變化 1.0 位以上才算改善／下降，可在規則設定修改。
- 成長／衰退依點擊增減判定，點擊相同時看曝光；前期沒有曝光的是「新出現」，目前沒有曝光的是「消失」。
- 沒有比較期間時，不標示新出現、消失、成長或衰退。

### 衰退熱圖

- 取最近 12 個完整日曆月。每格深淺＝該頁當月點擊 ÷ 該頁自己的最高月份，分 4 級。
- 「衰退中」＝最近 3 個月的月均點擊，比先前任一連續 3 個月的最佳月均低 30% 以上；高出 30% 以上是「上升中」。
- 有曝光的月份不足 6 個月標為「資料不足 6 個月」，最佳 3 個月合計不到 10 次點擊標為「點擊太少」，兩者都不下判斷。
- 排序先看衰退中，再看流失的月均點擊。季節性主題要和去年同期比，面板不替學員判斷原因。

### 新頁面

- 視窗是最近 182 天。在視窗之前（回溯到約 16 個月）沒有曝光、在視窗內第一次有曝光的頁面才算新頁面。
- 「首次」只在 GSC 可回溯的範圍內成立；更早有曝光、之後中斷超過 10 個月的頁面也可能出現。

### 排名追蹤

- 每個追蹤詞以「查詢完全等於」向 API 取得每日資料，不套用上方篩選。
- 主要曝光頁面＝該期間曝光最多的頁面；目前與前期的主要頁面不同時標「換頁了」。
- 關鍵詞清單匯入：每行第一欄，略過標題列與重複項，最多 500 個。

### 黃金距離與蠶食

- 黃金距離：平均排名 3–20（不四捨五入）且曝光達最低曝光門檻，依曝光排序。
- 蠶食：同一查詢有至少 2 個頁面，各自曝光達到 `max(最低曝光 ÷ 2, 該查詢曝光 × 10%)`。建議保留候選依點擊、曝光、平均排名的順序決定。品牌詞、Sitelinks 或不同意圖的頁面可能正常共存，合併或轉址前必須人工確認。

### 語言版本

只看網址：第一段路徑（`/fr/`、`/zh-tw/`）或三段以上網域的第一段（`fr.example.com`）符合 ISO 639-1 語言代碼就歸入該語言，其餘歸入「未標示語言」。不讀 hreflang；兩個字母的目錄剛好等於語言代碼時會誤判。最多顯示點擊最高的 8 組。

### 變更筆記

- 每則筆記比較變更日前 N 天與變更日起 N 天（7／14／28／56）。變更後的資料還不足 N 天時，前後都縮到相同的已有天數，並標示「已有 x / N 天」。
- 回看提醒日＝變更日 ＋ N ＋ 3 天；到期後導覽列會出現數字標記。
- 筆記會在總覽的走勢圖上顯示為標記。前後數字不同不等於是這次變更造成的。

### 索引檢查

逐一呼叫 `inspectUrl`，一次最多 200 個網址（預設 50）。`verdict` 為 `PASS` 視為已收錄，其餘顯示 Google 回報的 `coverageState`；Google 選的 canonical 與宣告的不同時另外標示。URL Inspection 有每日配額，結果是索引中的版本，不是即時測試。

### 資料匯出

維度可複選 `query`、`page`、`device`、`country`、`date`。查詢、頁面、國家、裝置篩選送往 API（支援 regex）；點擊、曝光、CTR、平均排名的數值區間在 API 回傳之後於瀏覽器內套用。CSV 會中和以 `=`、`+`、`-`、`@` 開頭的儲存格，避免被試算表當成公式。

## 行動佇列：deterministic 規則

規則排序分數只是面板內的優先順序，會受曝光量、排名區間與下降訊號影響；它不是 Google 分數，也不代表預測排名。同一查詢命中多條規則時合併成一筆，以分數最高的規則為主。

| 規則 | 預設觸發 | 面板行動文字 |
|---|---|---|
| `rewrite-11-20` | 平均排名 11–20，曝光至少 20 | 先用 Query 核對 SERP 與現有承接頁，再決定補強哪個缺口 |
| `rewrite-21-30` | 平均排名 21–30，曝光至少 20 | 先確認既有頁面、搜尋任務與第一方證據，再決定補強、合併或暫緩 |
| `decline-review` | 排名下降至少 1 位，且目前曝光至少 20 | 先核對比較期間、索引狀態與近期變更，再決定是否重寫 |
| `snippet-review` | 排名 1–10、曝光至少 20，且該 Query CTR 低於本站同排名區間 CTR × 0.75 | 先檢查 title、承諾與頁面是否對得上搜尋任務；不直接等於重寫 |
| `page-ownership-review` | 同一 Query 有至少 2 個 Page，各自達到最低曝光的一半 | 先分開看 Query → Page，再判斷正常多頁承接或需要整理頁面歸屬 |

- 異常變化：只在有比較期間時計算。預設標記排名下降至少 3 位、點擊下降至少 30%（前期至少 5 次點擊）或曝光下降至少 30% 的查詢。
- CTR 參考值＝**本站自己在同一排名區間的 CTR × 低 CTR 倍率**（區間：1、2、3、4–5、6–10、11–20、21+；該區間曝光不到 100 時退回全站 CTR）。不再用全站 CTR，因為品牌詞與第 1 名會把全站平均拉高。它不是業界基準。
- CTR 機會：排名 4–20、曝光達門檻、CTR 低於上述參考值的查詢。它是摘要／搜尋任務核對候選，不是保證可以增加點擊的預測。
- 最低曝光、排名變化幅度、低 CTR 倍率、候選數量、異常門檻都可在「規則設定」調整。調整只改排序與篩選，不改原始資料。
- 每筆候選可設定狀態（待確認／核對中／處理中／已完成／暫緩）與備註，並匯出 CSV。

## 教學使用順序

1. 先確認連線：面板顯示「GSC API 已連線」，再選網站資源與期間。還沒接好時用示範資料帶學員認識分頁，並明講那是合成資料；要接就走 `65-gsc-api-setup.md`，一輪一步。
2. 從總覽開始：先讀四個指標與走勢，再看排名分桶，只挑一個成長與一個衰退的查詢討論。
3. 依問題進分頁：內容衰退看衰退熱圖，接近首頁看黃金距離，多頁承接看蠶食檢測，收錄問題看索引檢查。
4. 打開行動佇列，說明它只提供「人工核對候選」；下一步回到當下 SERP、承接頁與網站能否可信提供。
5. 完成一項修改的當天記一則變更筆記，等回看提醒到期再用前後同天數比較。
6. 學員要回報時按「複製證據卡」貼給教練，不必截整個畫面。

不要把面板計算、GSC 平均排名、佇列排序或變更筆記的前後差異當成排名改善的證明。真正的修改成效仍需要修改前基準、真實頁面重驗與適當時間窗口後的 GSC／其他第一方資料。
