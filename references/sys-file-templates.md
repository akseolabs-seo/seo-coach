# 檔案模板

這個 skill 會在**完整陪跑模式**下，在用戶的資料夾內建立兩個檔案，用來記錄進度和行動清單。輕量模式預設不落盤。

第三個檔 `seo-ga4-log.md` **只在第一次拿到 GA4 數字時才建立**，不是每個用戶都會有。

## seo-ga4-log.md 模板（GA4 數據台帳）

**建立時機**：完整陪跑模式下，第一次拿到 GA4 數字（截圖／API／用戶口述）的那一輪就建，不要等 session 結束。輕量模式不建，除非用戶答應存檔。

```markdown
# GA4 數據台帳 — [網域]
<!-- 只增不刪：新紀錄加在表格最上面。只寫本輪實際看到的數字，來源必填。 -->
最後更新：[YYYY-MM-DD]

## 基準線
GA4 開始收資料：[YYYY-MM-DD / 不確定]
資料保留設定：[2 個月 / 14 個月 / 未確認]
關鍵事件：[事件名稱 / 尚未設定]
已連結 GSC：[是 / 否]
主要資料來源：[用戶截圖 / Data API]
目前解鎖到：[L1 / L2 / L3 / L4 / L5 / L6]

## 紀錄
| 記錄日 | 期間 | 指標 | 數值 | 來源 | 比上次 | 當時發生什麼 |
|--------|------|------|------|------|--------|--------------|
| [YYYY-MM-DD] | [過去 28 天] | [Organic Search 工作階段] | [412] | [截圖/API/用戶口述] | [+8% / 基準線] | [改了首頁 title] |

## 待校正
<!-- 來源是「用戶口述」的數字放這裡，下次拿到截圖或 API 就補正並移除 -->
- [日期]：[指標] [數值]（用戶口述，待截圖確認）
```

**「當時發生什麼」不能留空。** 改了 title、發了新文、換模板、動了 robots.txt 都寫進去——三個月後看到波動，這一欄是唯一能把時間線對起來的東西（跟 GSC annotation 同一個作用，見 `24-gsc-guide.md`）。

## 更新規則

- **seo-progress.md**：每次 session 結束時覆寫整個檔案
- **seo-actions.md**：每次 session 結束時更新，保留用戶已打的 [x]，只新增/修改項目，不刪除用戶的記錄
- **seo-actions.md 去重**：同一個問題如果已經存在，就更新原條目，不重複新增；完成後只移到 `✅ 已完成` 一次
- **seo-ga4-log.md**：拿到數字**當輪就寫**，不等 session 結束；先讀取再新增，只增不刪；同一天同一指標重複回報時更新該列，不新增重複列
- **三個檔共通**：寫入前先讀取比對現有內容，不直接覆寫用戶的紀錄
