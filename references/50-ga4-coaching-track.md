# 50 — GA4 陪跑軌道（指路卡 + 逐級解鎖）

**reason**: GA4 的知識網路上到處都有，新手缺的不是解釋，是「我現在該點哪裡、該看哪一個數字、這個數字能不能拿來下判斷」。本檔把 GA4 拆成一次一張指路卡，讓用戶在自己的帳號裡一級一級累積理解。
**strip_when**: GA4 把本檔的報表路徑整批改名或合併，且指路卡無法用現行選單完成同一個判斷。

資料核對：2026-07-29。GA4 介面分批推送，**選單字樣在不同語言與版本之間不一致**（繁中常見「客戶開發 → 流量開發」，也有版本／簡中寫「獲取 → 流量獲取」）。本檔每個路徑同時列出兩種中文字樣與英文原名，**英文名是最穩的錨點**；仍以用戶截圖為準，找不到就走備援路徑（GA4 左上搜尋列直接打報表名稱）。判斷邏輯不隨介面改名而變。

---

## 這條軌道解決什麼

**GSC 管「搜尋結果頁之前」**：誰搜了什麼、有沒有看到你、有沒有點進來。
**GA4 管「進站之後」**：他從哪個管道來、待了多久、做了什麼、有沒有完成你要的事。

兩邊的數字對不起來是正常的，不是有一邊壞掉。

新手打開 GA4 的第一個失敗，通常不是不懂名詞，而是**首頁一堆卡片，不知道哪一張跟自己的問題有關**，於是每個都點一遍，越點越亂。所以這條軌道只有一條核心規則：

> **先有問題，才開 GA4；一輪只給一張指路卡。**

---

## 什麼時候開這條軌道

**開**：
- 用戶問「我做的 SEO 有沒有用」「流量有沒有變多」「哪一篇文章有用」「進來的人有沒有下單」
- 進入 Module 18（SEO 成效衡量，`21-seo-measurement.md`）
- 已完成至少一個 Tier 1 檢查，而且 GA4 已經在收資料

**先不要**：
- 完全新手第一輪 → 先跑 `36-beginner-practical-playbooks.md` 的 5 分鐘檢查
- GA4 裝好還不到 48 小時 → 資料還沒累積，看到 0 會誤判成裝壞了
- 問題其實屬於搜尋端（有沒有被收錄、排第幾、用戶搜什麼字）→ 走 `24-gsc-guide.md`，不要用 GA4 回答 GSC 的問題
- 還沒裝 GA4 → 先 `23-ga4-basics.md` 的安裝段，裝完等一天再回來

## 指路卡格式（每輪只給一張）

**七項是內容清單，不是七段。** 輸出時壓成 **3–4 段**（例：路徑＋看哪個數字一段、常見誤讀一段、換你做一段），符合主檔的回應深度規則。

1. **這張卡回答的問題** — 用用戶自己的話寫，一句
2. **精確路徑** — GA4 選單逐層寫到底，中文字樣有兩種就都給、後面附英文原名；附備援：「找不到就在左上搜尋列打『報表名稱』」
3. **你會看到什麼** — 畫面長相，讓用戶確認自己沒點錯
4. **只看這一個數字** — 指名欄位，其他先不管
5. **常見誤讀** — 一條就好，挑最容易讓新手自己嚇自己的那條
6. **怎麼判斷** — 用相對比較（跟自己的上一期、跟同站另一頁）給分界，不給業界絕對值
7. **換你做** — 同型的下一個判讀，或回報形狀（「截圖貼上來就行」）

卡片結束時把這一級解鎖的概念寫進 `seo-progress.md` 的已學術語，下次直接用不重教。

## 拿到任何一個 GA4 數字時，一定做的三件事

**不用等用戶問。** 只要本輪出現了 GA4 數字（用戶截圖、用戶口述、或 API 回傳），三件事一起做完，合計 3 句以內，不要膨脹成三段：

1. **先翻譯** — 這個數字在算什麼，一句人話。不要等用戶問「這是什麼意思」才講；新手多半不知道自己該問。
   > 「這個 412 是『工作階段』，不是 412 個人——同一個人今天來三次會算三次。」
2. **再定位** — 跟台帳上次同一個數字比。第一次就明講這是基準線。
   > 「上次是 380，這 28 天 412，往上。」／「這是我們第一次記，先當基準線，下次才有得比。」
3. **後記錄** — 寫進 `seo-ga4-log.md`，並讓用戶知道你記了。
   > 「我記進台帳了，下次你不用重找，我直接跟這個數字比。」

**記錄的誠實規則**：只寫本輪真的看到的數字，來源要標清楚（`截圖` / `API` / `用戶口述`）。沒看到就不要寫，也不能用「通常會是這樣」填空。用戶口述的數字照記，但來源標 `用戶口述`，下次有截圖或 API 再校正。

## 主動說明涵義的觸發表（畫面出現就當場講，不等用戶問）

新手不會問他不知道存在的問題。以下情況只要在截圖或回傳裡出現，**一句話當場講掉**，不要留到用戶自己踩坑：

| 畫面上出現 | 當場講的那一句 |
|-----------|---------------|
| Direct 佔比很高 | Direct 是 GA4 認不出來源時的統稱（書籤、App、被剝掉的參數都算），不代表都是老客戶 |
| 工作階段明顯大於使用者 | 同一個人可以有多個工作階段——超過 30 分鐘沒動作就切成新的一段 |
| `(not set)` / `(other)` | 那是歸類不到的資料，不是錯誤；佔比小就先忽略 |
| 參與率看起來偏低 | GA4 的「參與」有定義：>10 秒、或看 2 頁以上、或觸發關鍵事件；一句話答完的頁面天生就低 |
| 關鍵事件／轉換 = 0 | 很可能只是還沒標記關鍵事件，不代表沒生意 |
| 用戶在看「今天」的數字 | 報表有處理延遲，看昨天以前的才穩，今天的數字不能拿來判斷成效 |
| 折線圖最後一段往下墜 | 最後一天資料還沒收完，那個下墜通常是假的 |
| 資料保留還是 2 個月 | 現在就去改成 14 個月，越晚改能回溯的越少（管理 → 資料設定 → 資料保留） |
| GA4 數字和 GSC 對不起來 | 兩邊量的東西不同，差 10–20% 正常，超過 30% 才值得排查 |

一輪最多講**一條**（跟一輪一個核心概念的規則一致）。同時命中多條時，挑最可能讓用戶做出錯誤決定的那一條。

## L1 — 「我的 GA4 到底有沒有在收資料？」

**路徑**：報表 → 即時（Realtime）。備援：左上搜尋列打「即時」。
**你會看到**：一張「過去 30 分鐘的使用者」數字卡，旁邊通常有地圖和一串事件名稱。
**只看**：過去 30 分鐘的使用者數。
**做法**（3 分鐘）：另開一個分頁打開自己的網站首頁、重新整理一次，回來看數字有沒有 +1（可能延遲數十秒）。
**常見誤讀**：看到 0 不一定是沒裝好——你裝了廣告阻擋外掛、或自己的 IP 被排除在流量之外，都會看不到自己。
**怎麼判斷**：有 +1 → 有在收，可以往 L2。完全沒動 → 換一支手機、關掉 Wi-Fi 用行動網路再試一次；還是 0 才是安裝問題，回 `23-ga4-basics.md` 的安裝與驗證段。
**換你做**：截一張即時報表的圖貼上來就行，不用打字描述。

**解鎖概念**：GA4 的數字是網頁上一段追蹤碼主動回報的，所以它只看得到「成功載入頁面而且沒被擋掉的人」——這就是它跟 GSC 天生對不齊的原因。

## L2 — 「有多少人是從 Google 自然搜尋來的？」

**路徑**：報表 → **客戶開發／獲取**（Acquisition）→ **流量開發／流量獲取**（Traffic acquisition）。備援：搜尋列打「流量開發」或「流量獲取」。
把第一欄（維度下拉）切成「工作階段主要管道群組」（部分帳號寫「工作階段預設管道群組」，同一件事）。右上日期改成「過去 28 天」。
**你會看到**：一張表，左邊是 Organic Search / Direct / Referral / Social 這類管道名稱，右邊是工作階段、使用者、參與率等欄位。
**只看**：Organic Search 那一列的「工作階段」。
**常見誤讀**：把 Direct 當成「沒有來源、都是老客戶」。Direct 是 GA4 認不出來源時的統稱——書籤、App 內開啟、部分手機瀏覽器、被剝掉的追蹤參數都會掉進去。Direct 很高不等於品牌很強。
**怎麼判斷**：不看絕對值。右上日期選單勾「比較」→「前一期間」，看 Organic Search 這一列這 28 天 vs 前 28 天的變化方向。
**換你做**：告訴我兩個數字就好——這 28 天的 Organic Search 工作階段，和比較期的。

**解鎖概念**：**工作階段 ≠ 使用者**。同一個人今天來三次算 1 個使用者、3 個工作階段（超過 30 分鐘沒動作就切成新的一段）。所以工作階段數通常比使用者數大，這正常。

---

## L3 — 「是哪幾頁在帶自然搜尋流量？」

**路徑**：報表 → **參與度／參與**（Engagement）→ **到達網頁**（Landing page）。備援：搜尋列打「到達網頁」。
加篩選：報表上方「新增篩選器」→ 維度選「工作階段主要管道群組」→ 值選 Organic Search → 套用。
**你會看到**：一張表，左邊是網址路徑（`/`、`/about`、`/blog/xxx`），右邊是工作階段等指標。
**只看**：前 5 列的到達網頁 + 工作階段。
**常見誤讀**：`(not set)` 不是某一個頁面，是 GA4 歸不到到達頁的工作階段（跨天的工作階段、直接觸發的事件都會落在這）。佔比小就先忽略，不用去修。
**怎麼判斷**：如果你花最多力氣寫的那一頁不在前 5 名，那頁就是下一個要查的對象——回 GSC 看它有沒有曝光，區分是「Google 沒讓人看到」還是「看到了但沒人點」。
**換你做**：貼一張前 5 列的截圖，我們一起看第 1 名是不是你以為的那一頁。

**解鎖概念**：**維度 vs 指標**。到達網頁是維度（是誰），工作階段是指標（有多少）。GA4 幾乎每一張報表都是「一個維度 × 幾個指標」，看懂這個組合，任何沒看過的報表都能自己讀。

---

## L4 — 「進來的人有沒有真的在看？」

**路徑**：同 L3 的到達網頁報表，往右看「平均參與時間」「參與工作階段數」「參與率」。
**只看**：你關心的那一頁的參與率。
**常見誤讀**：參與率低不等於內容爛。GA4 對「參與」有明確定義——停留超過 10 秒、或看了 2 頁以上、或觸發過一次關鍵事件，三者之一即算。所以一句話就回答完的頁面（營業時間、聯絡方式）天生參與率低，那是頁面性質，不是品質問題。
另外：GA4 的跳出率 = 100% − 參與率，跟舊版 GA「只看一頁就走」的定義不一樣，不要拿舊經驗直接比。
**怎麼判斷**：拿**同一個網站、同一種類型的兩頁**互相比，不要跟業界數字比。差距明顯時再問「這兩頁差在哪」。
**換你做**：挑兩篇性質接近的文章，把它們的參與率念給我聽，我們一起看差在哪。

**解鎖概念**：**GA4 裡一切都是事件**。page_view、scroll、click 全是事件，報表上的指標其實都是事件的加總。理解這件事之後，L5 的「關鍵事件」就只是「你標記出來的那個事件」。

---

## L5 — 「這些流量有沒有帶來我要的結果？」

**先問用戶一個問題**：你的網站上「成功」長什麼樣？（送出表單／點電話／加入購物車／看到感謝頁）沒有答案就不要往下設，先把這題聊清楚。

**路徑（看有哪些事件）**：報表 → **參與度／參與**（Engagement）→ **事件**（Events）。
**路徑（標記關鍵事件）**：管理 → 資料顯示 → 事件 → 找到那個事件 → 打開「標示為關鍵事件」。
新版介面叫**關鍵事件（Key events）**，舊介面叫**轉換（Conversions）**，是同一件事；用戶截圖是哪個字就跟著用哪個字。
**只看**：關鍵事件次數，以及它在「流量獲取」報表裡 Organic Search 那一列的數字。
**常見誤讀**：沒設關鍵事件時，報表上的轉換是 0，不代表沒生意——只代表沒人告訴過 GA4 什麼叫成功。
**怎麼判斷**：有數字之後，看的是「自然搜尋帶來的關鍵事件 ÷ 自然搜尋工作階段」的趨勢，不是單月絕對值。
**邊界**：表單送出、按鈕點擊這類**自訂事件的實作（GTM、埋 code）超出陪跑範圍**。我可以幫你確認該追什麼、看懂結果；實作交給工程或熟 GTM 的人。

**解鎖概念**：**關鍵事件是你自己定義的**。GA4 不知道你的生意怎麼算成功，你不標記，它就永遠回報 0。

---

## L6 — 「哪個搜尋字帶來的人最會轉？」（需先連 GSC）

**前置**：GA4 → 管理 → 產品連結 → Search Console 連結 → 選你的 GSC 資源。
連完還有一步，很多人卡在這裡：報表 → 資料庫（Library）→ 找到「Search Console」收藏集 → 發布，左側選單才會出現這個報表。
**路徑**：報表 → Search Console → 查詢 ／ 自然搜尋流量。
**只看**：挑一個查詢字，看它的點擊，再看它對應到達頁的參與率。
**常見誤讀**：這裡的點擊來自 GSC、工作階段來自 GA4，兩個數字不會相等，差 10–20% 是常態，不用去查「哪邊壞了」。
**怎麼判斷**：找「點擊多但參與率低」的字——那通常代表用戶搜的意圖跟你的頁面內容有落差，是最值得改的一種。

**解鎖概念**：**GSC 管搜尋前、GA4 管進站後**，接起來才看得到「哪個字帶來的人真的有用」。

## 一定要先講清楚的 6 個誤讀

新手在 GA4 自己嚇自己，幾乎都是踩到這六條之一。碰到就當場講一條，不要六條一起倒。

1. **GA4 和 GSC 數字不會一樣。** 一個算工作階段、一個算點擊；擋追蹤的瀏覽器 GA4 看不到、GSC 看得到。差 10–20% 正常，超過 30% 才值得排查。
2. **Direct 不是「沒有來源」。** 那是 GA4 認不出來源的統稱，不代表都是回頭客。
3. **`(not set)` 和 `(other)` 是歸類不到，不是錯誤。** 佔比小就忽略。
4. **報表有處理延遲。** 事件與多數報表通常要數小時到 24–48 小時才穩定。看昨天以前的資料最保險，不要用「今天」的數字判斷成效。
5. **資料保留預設只有 2 個月。** 管理 → 資料設定 → 資料保留，可以改成 14 個月（影響探索報表能回溯多久；標準報表不受此限）。**越晚改能回溯的越少，這是第一天就該做的一步。**
6. **小樣本不要下判斷。** 一天只有 20 個工作階段的網站，「參與率掉了 5%」什麼都不能證明。另外，開了 Google 信號的資源在資料量少時會觸發資料閾值，某些列會直接被藏起來——那是隱私機制，不是資料掉了。

## 數據台帳：`seo-ga4-log.md`

完整陪跑模式下，**第一次拿到 GA4 數字時建立**這個檔（模板與更新規則 → `sys-file-templates.md`）。輕量模式不建，除非用戶答應存檔。

它跟 `seo-progress.md` 的差別：progress 每次覆寫，台帳**只增不刪**。沒有台帳，「這個月比上個月好嗎」永遠只能靠用戶記憶回答。

- 每次拿到數字就加一列，不要等 session 結束才補
- 每列都有「當時發生什麼」欄位——改了 title、發了新文、換了模板都寫進去。三個月後看到波動，這一欄是唯一能把因果對起來的東西
- 台帳裡也記基準線資訊：GA4 開始收資料的日期、資料保留設定、關鍵事件有沒有設、GSC 連了沒
- 寫入前先讀取比對，不覆蓋舊列

---

## 這條軌道的教練規則

- **一輪一張卡。** 用戶問一個問題，就給對應的那一張，不要順便把下三張也講完。
- **主動翻譯、主動記錄。** 數字一出現就做上面的三件事，不等用戶問；命中觸發表就當場講掉那一句。
- **截圖優先。** 一律主動說「直接截圖貼上來就行，不用打字描述」；收到截圖先用人話描述看到什麼，再問一個問題。
- **不偽造觀察。** 只有本輪拿到用戶截圖或 API 實際回傳，才可以說「我看到你的⋯⋯」。沒有就說「打開之後告訴我那個數字」。
- **設定類要留退路。** 標記關鍵事件、改資料保留這類設定，給步驟時附上「改錯會怎樣、怎麼改回來」。
- **不代做設定。** GA4 帳號權限與事件實作是用戶的；教練給路徑與判準。
- **記住已解鎖的概念。** 工作階段／管道群組／維度 vs 指標／事件／關鍵事件，學過就直接用，不重講。
- **邊界**：事件追蹤實作、GTM 設定、自訂維度、歸因模型比較、BI 整合 → 給方向與判斷，不做實作（→ `23-ga4-basics.md` 邊界聲明）。
