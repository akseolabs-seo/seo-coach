# 62 — GSC 成效變化診斷練習

**reason**：教學員把 GSC 的現況、期間變化與頁面判斷分開，能處理接近首頁、內容衰退與多頁承接等常見問題，而不把一列資料直接當成根因。
**strip_when**：若 skill 不再教 GSC 成效變化或頁面判讀，才移除；單純問面板格式與公式時只讀 `59-gsc-dashboard.md`。

這份文件是面板之後的教學判讀層。面板提供可重做的聚合與候選排序；本文件負責教學員提出假設、回到 SERP 與頁面、選一個可驗證動作。

## 先確認資料能不能比較

在說「上升」「下降」「消失」前，先核對：

- 同一 property、查詢／頁面維度、地區、裝置與搜尋類型；
- 目前與比較期間的日期長度和季節條件相近；
- 是否有資料列上限、匿名查詢、省略維度或 `partial`；
- GSC 的平均位置是期間彙總，不是某個人此刻看到的即時名次。

只有目前期間可以看現況分布，不能證明成長或衰退。不同範圍的兩份資料只能標為不可直接比較，不能用差異補出因果故事。

回覆 GSC 比較問題時要把這句白話說出來：**目前期間可以看現在的分布；要說上升、下降、新出現或消失，才需要可比的前期資料。** 這不是要求學員先拿齊整站資料，而是先把能說與不能說的範圍分開。

若目前期間不可比，這一輪在取得同長度、同範圍截圖後就停；不要先列曝光、CTR、季節、整站或單頁的所有分支。等學員回傳新證據，再只選一個最能區分的下一步。

## 練習 A：接近首頁的查詢

位置約在 4–15 的查詢可以作為人工複核佇列範例，不是保證會進首頁的門檻。先看曝光與點擊的同期間資料，再做一個最小核對：

1. 查詢與目前承接頁的讀者任務是否吻合；
2. 在相同地區、語言、裝置和日期條件下手動看當下 SERP；
3. 看 title、頁面開頭、必要答案和第一方證據是否兌現承諾；
4. 只選一個補強、標題調整、頁面差異化或暫緩觀察的動作。

不要把 CTR 與排名區間當成通用正常值，也不要因一列符合排序規則就整篇重寫。候選要回到搜尋意圖、頁面內容與修改後重驗。

## 練習 B：內容或查詢衰退

用相同期間定義先確認變化，再拆開觀察點：點擊、曝光、CTR、平均位置、查詢、頁面和資料完整度。接著只選一個分流問題：

- 需求或季節改變？查看同主題其他查詢或較長時間趨勢。
- 整站都變？查看索引、技術、改版、模板或手動操作等時間線。
- 只有一頁或一組查詢變？回到頁面、意圖、內容新鮮度和 SERP。
- 只有點擊變但曝光不變？先核對摘要承諾、頁型與裝置，不直接宣稱 title 是唯一原因。

可能的結果是 `refresh`、`rewrite-or-reframe`、`differentiate`、`consolidate-review`、`defer` 或 `observe`。保留現有有用內容；沒有頁面、SERP 與基準證據時，不先刪除、重導或整篇重寫。

## 練習 C：多頁承接與頁面競爭候選

同一查詢出現多個 URL，只能說有頁面歸屬候選。確認前要看：

1. 查詢－頁面明細是否真的是同一期間、同一維度；
2. SERP 是否在不同時間或條件下交替顯示兩頁；
3. 兩頁的讀者任務、頁型、證據與下一步是否真的相同；
4. 合併、保留並差異化、指定主要承接頁、暫緩，哪個方案風險最低。

沒有這些證據，不自動 canonical、redirect、刪頁或合併。若頁面任務本來不同，保留兩頁可能是正確結果。

若 GSC 的 property、期間與維度已經確認相同，本輪只做一個真正能區分解釋的檢查：在相同地區／語言／裝置的無痕視窗看該查詢目前是否交替顯示兩個 URL，並用各自的標題承諾說明任務是否相同。若資料範圍尚未確認，先把範圍確認標成前置依賴，不把它誤說成已證明頁面競爭。

## 練習 D：讀索引狀態

來源是面板「索引檢查」或 `inspect`（→ `65-gsc-api-setup.md`）回傳的 `coverageState`；沒接 API 就看 GSC 網址審查的同一句話。它是索引中的版本，不是即時測試；一次只讀一個網址。

| `coverageState` | 白話 | 做／放著／等 |
|---|---|---|
| Submitted and indexed／Indexed, not submitted in sitemap | 已收錄 | 放著；記成健康基線。後者只代表 sitemap 沒列它 |
| Discovered - currently not indexed | Google 知道網址，還沒來抓 | 等；先確認有內鏈指向它，不反覆要求建立索引 |
| Crawled - currently not indexed | 抓過了，這次沒收 | 做一個核對：這頁和站內其他頁的差異與完整度；不是技術錯誤 |
| Alternate page with proper canonical tag／Page with redirect | 你指定了別的網址當正式版 | 多半是預期中的放著；非預期才查 canonical 或轉址 |
| Duplicate without user-selected canonical／Duplicate, Google chose different canonical than user | Google 選了另一頁當正式版 | 做：比對兩頁是否真的重複，再決定宣告 canonical 或差異化 |
| Excluded by 'noindex' tag／Blocked by robots.txt | 你（或外掛）要求不要收 | 想被收錄才做：先留底再改（→ SKILL.md 改動前留底） |
| Not found (404)／URL is unknown to Google | 頁面不存在，或 Google 沒見過 | 先確認網址打對；該存在的頁面才處理 |

## 練習 E：新頁面的軌跡

面板「新頁面」只在 GSC 可回溯範圍內成立。先看首次曝光日與每日曝光走勢，再問一題：曝光有在累積嗎？有 → 等，並在詳情抽屜看它開始接到哪些查詢；發布數週仍無曝光 → 回練習 D 查那一頁的索引狀態。新頁面排名浮動是常態，前幾週不拿平均排名下結論，也不因此改標題。

## 練習 F：語言版本

面板只靠網址辨識語言（不讀 hreflang）。只做一個比較：某個語言版本的走勢和主站是否同向。同向 → 多半是整站因素；只有一個版本變 → 回到該語言的查詢與頁面。不同語言的 CTR 與排名不互相當基準；兩字母目錄誤判成語言時標成資料限制。

## 練習 G：讀一則變更筆記

1. 一則筆記只對一個改動；同一週改了兩件事就寫成兩則，並承認分不開。
2. 視窗長度先選好再看（title／摘要類常用 14 或 28 天）；「已有 x / N 天」不足時只說趨勢未定。
3. 列出同期間的干擾：季節、Google 更新（總覽圖的標記）、其他改版、索引狀態改變。
4. 結論只有四種：保留／回復／延長觀察／`inconclusive`。點擊太少、視窗不完整或有干擾排不掉，就寫 `inconclusive`，它是合格結果。

## 練習 H：曝光上升但 CTR 下降

先分清是哪一種，一輪只查一個：

- 新增的曝光來自排名較後的新查詢 → 整體 CTR 被稀釋，不是變差（在詳情抽屜看該頁的查詢是否變多）。
- 同一批查詢、排名相近，CTR 卻掉 → 假設是 SERP 版面變了：AI 摘要、更多廣告或其他搜尋結果功能佔走點擊。這是**待查假設**，要用無痕視窗看當下 SERP 才能支持；GSC 沒有欄位能直接證明。
- 排名也往後 → 回練習 B。

面板的 CTR 參考值是本站同排名區間的 CTR，不是業界基準（→ `59-gsc-dashboard.md`）。

## 練習 I：內容衰退決策卡

入口是衰退熱圖標為「衰退中」的一頁；先點開該頁的詳情抽屜，看掉的是哪些查詢。「資料不足」「點擊太少」的頁面不進這張卡。

| 看到什麼 | 決定 | 先確認 |
|---|---|---|
| 查詢還在、排名往後，內容有過期處 | 更新 | 和去年同期比，排除季節 |
| 站內另一頁接走同一批查詢 | 合併複核 | 走練習 C，確認兩頁任務相同 |
| 主題已不再提供，且有明確的接替頁 | 轉址 | 留底；沒有對應頁就不硬轉 |
| 需求本身變少，或這頁對業務已不重要 | 放著 | 寫下理由與下次回看日 |

一次只決定一頁；決定後記一則變更筆記，回看方式照練習 G。

## 教學輸出卡

```markdown
GSC 觀察：目前／比較期間、範圍與實際變化
資料限制：缺少什麼，哪些列可能不完整
目前假設：一句話
回到 SERP／頁面的核對：一項
行動：[補強 / 差異化 / 合併複核 / 暫緩 / 觀察]
修改前基準：
完成與回復方式：
回看日期與同定義指標：
```

新手只做一個區分檢查；熟悉後再比較多頁或多組查詢。判讀完成的條件是能說出資料支持什麼、不能支持什麼，以及下一個結果出現時要如何改變決策。
