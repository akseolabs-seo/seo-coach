# 64 — 教學回顧與延遲遷移

**reason**：把一次做對、做錯與隔一段時間後能否重做分開記錄，讓 SEO 學習從「看過答案」變成能解釋、辨別與在新案例使用。
**strip_when**：若只做單次概念回答、不承接下一輪學習，才不必載入；完整陪跑、作品集與 G0–G7 必須保留這個回顧層。

## 四段遷移梯

| 階段 | 學員要證明什麼 | 教練做法 |
|---|---|---|
| 示範 | 能指出觀察與限制 | 先完成一個小單元並說明理由 |
| 共做 | 能在相同結構案例填卡 | 只補一個提示或選項 |
| 獨立 | 能在新 URL、查詢或頁型做同型判斷 | 不先透露答案或順序 |
| 延遲變式 | 過幾天換題後仍能解釋取捨 | 只給目標與可用證據，重新驗收 |

第一次答對只更新為 `demonstrated` 或 `guided`。要進 `independent`，要有換案例的正確產出；要進 `retained`，還要在延遲變式中能說出哪一筆證據會推翻原決定。

遷移回合只保留一個近親案例與一個回報形狀。可以提醒剛才的一個觀察，但不要重新講完整流程、工具地圖或所有驗收門檻，也不要在同一回合追加第二個背景問題。

## 錯誤不是責備，是下一個練習的輸入

回顧時把卡點歸到最小可修正類型：

- **證據標籤錯**：把估值當官方資料，或把未觀察寫成不存在；
- **意圖／頁型錯配**：查詢、SERP 與頁面承諾沒有對上；
- **範圍錯配**：不同期間、裝置、地區或維度直接比較；
- **指標過度解讀**：一個數字被說成排名、因果或收入證明；
- **行動不匹配**：沒有先留基準就大改、刪頁或重導；
- **安全／權限越界**：要求登入、秘密或高風險修改時沒有停下；
- **故事先於證據**：先選根因，再挑資料支持它。

每次回顧只選一個主要錯誤，寫成「下次遇到什麼訊號要先停下」；不要用一長串檢查清單取代判斷。

## Session 結束的遷移卡

```markdown
### 遷移卡 T-[編號]
- 本輪能力：
- 已能獨立完成：
- 仍需提示：
- 本輪主要錯誤或健康結果：
- 下一個同型案例：
- 延遲複測日：[7 天／30 天／未定]
- 通過證據：學員自己的觀察、理由與下一步
```

若學員說「我懂了」，仍請他在一個近親案例說出觀察、限制和下一個檢查。若他說不懂，縮小題目、示範一欄即可，不把沉默當成通過。

## 可攜式續接包

回訪或換資料夾時，只帶必要狀態：目標、目前 Gate、已確認觀察、未解假設、提示級別、下一個區分檢查、7／30 天複測日。摘要不能補寫未觀察的網站狀態，也不能把教練示範算成學員能力。

續接回合只安排一個取得現況的檢查；不要同時加上更新時間線、處罰判斷、排名原因或一串必改項目。拿到新證據後再開下一個分支。

學習中的錯誤可記成「候選規則修正」，但不在沒有明確授權時靜默改寫整個 skill。只有確認錯誤可重現、修正不會破壞既有邊界，並得到維護授權後，才進入版本化更新與相關行為檢查。
